# Конвейеры оболочки

Это руководство запускает сервис как одну ступень конвейера оболочки, `producer | stage | consumer`.

[`StdioBroker`](../components/broker/stdio-broker.md) читает стандартный ввод процесса как поток и пишет в его стандартный вывод.
Подписка читает строки одного ключа потока, а публикация пишет строку для следующего процесса.

Пример - ступень расчёта цен: она читает заказы и отвечает на каждый квитанцией.

`price` читает строки под ключом `orders` и отвечает квитанцией `Receipt`, которая уходит в стандартный вывод под ключом `receipts`.
Ступени нужен [`out_retry(Publish).to(..)`](../components/settlement/out-retry.md), хотя `price` никогда не повторяет обработку.
В канале отложенная копия может уйти только на следующую ступень, поэтому каждая регистрация называет ключ, и без него ступень не запускается.

## Строка {/* #the-line */}

Строка - это заголовок в квадратных скобках, а за ним полезная нагрузка ([Строки](../components/subscriptions/lines.md)):

```text
[timestamp | stream_key | sequence | shard_id] payload
```

Каждое поле заголовка необязательно, поэтому продюсер обычно пишет только ключ:

```bash
echo '[orders] {"id":7,"quantity":3,"unit_cents":250}' | ./pricing run
```

Строка под другим ключом пропускается, поэтому несколько ступеней могут забирать из одного потока каждая свои ключи.
Строка без заголовка не называет ключа, и клиент передаёт её каждой подписке ступени.
Поэтому инструмент, который пишет простые строки JSON, подаёт их всем обработчикам сразу:

```bash
jq -c '.[]' orders.json | ./pricing run
```

Клиент разбирает заголовок каждой строки до того, как её увидит сервис, а строка, которую он не может разобрать, останавливает весь процесс.
Так действуют строки двух видов: ввод не в UTF-8 и начальные скобки `[...]`, которые не являются заголовком, например массив JSON.
Продюсер такой полезной нагрузки пишет перед каждой из них заголовок.

## Вывод {/* #the-output */}

Ступень пишет по строке на каждую публикацию, с заголовком, который заполняет клиент:

```text
[2026-10-18T15:08:01 | receipts | 0] {"order":7,"total_cents":750}
```

Метка времени - это время записи с точностью до секунды, а порядковый номер считает строки каждого ключа с нуля.
Инструмент, который читает простой JSON, берёт полезную нагрузку после заголовка:

```bash
./pricing run < orders.txt | sed 's/^\[[^]]*\] //' | jq .total_cents
```

Полезная нагрузка, которую изменила бы текстовая строка, уходит в [конверте](../components/headers/payloads.md): двоичная, с переводом строки или с пробельными символами в начале или в конце, а также каждое сообщение с заголовками.
Конверт - это строка, которая начинается с `rs1:` или `rs2:`. Он предназначен для следующей ступени RustStream: она вскрывает конверт и передаёт своему обработчику опубликованные байты и заголовки.

Журнал уходит в стандартный поток ошибок через `tracing`, поэтому никогда не смешивается с сообщениями.
Строка, напечатанная в стандартный вывод через `println!`, доходит до следующей ступени как строка без ключа, и её читает каждая подписка этой ступени.

## Цепочки ступеней {/* #chaining-stages */}

```bash
./intake run < orders.txt | ./pricing run | ./billing run
```

Каждая ступень читает ключи, на которые подписана, и пишет свои ответы для следующей.
Заголовки и двоичная полезная нагрузка проходят каждый канал целиком, потому что каждая ступень вскрывает конверты, записанные предыдущей.
Ступень, которая откладывает повторную обработку, отправляет свои копии дальше по конвейеру под ключом, который называет её точка монтирования, и их читает одна из следующих ступеней, как показывает руководство [Повторы и ключ dead-letter](retries.md).

## Тестирование ступени {/* #testing-the-stage */}

Файл примера тестирует ступень на внутрипроцессном транспорте: [`TestApp::start`](../components/testing/index.md) запускает её, `tb.broker::<StdioBroker>().message(..)` подаёт строку с заказом, а `published::<Receipt>("receipts")` читает записанную ступенью строку.

Живые тесты запускают собранную ступень с перенаправленными стандартными вводом и выводом.
Они проверяют, что ступень отвечает на строки `orders` и на строки без ключа, пропускает другой ключ и останавливается на строке с массивом JSON и на вводе не в UTF-8.
[`loopback`](../components/broker/loopback.md) подаёт ступени её собственный вывод, поэтому две ступени работают в одном процессе, и один тест управляет обеими.
