# Журнал событий на диске

Это руководство записывает события магазина в файл потока, читает их по мере записи и подводит итоги законченного файла за один проход.

Файл потока - это журнал: публикация дописывает сообщение под ключом потока, и каждый читатель ключа видит сообщения по порядку.
Пример - магазин, который записывает квитанцию на каждый заказ, и задание аудита, которое подводит итог квитанциям законченного файла.

`checkout` отвечает на каждый заказ квитанцией `Receipt`, и ответ дописывается в тот же файл под ключом `receipts`, который объявляет тип.
Один файл хранит все ключи потока, поэтому путь указывается один раз, в `FileBroker::new`.
Публикация дописывает сообщение и сбрасывает его в файл, поэтому байты попадают в операционную систему до возврата из вызова.
Файл синхронизируется с устройством при [завершении работы](../components/broker/shutdown.md) брокера.

`notify` читает `receipts` от конца файла и получает каждую квитанцию, как только `checkout` её допишет.
Другой процесс, который открывает тот же путь, читает ключ точно так же.
Подписка без [позиции](../components/positions/start-at.md) начинает с конца, поэтому перезапущенный `notify` читает только квитанции, записанные после его запуска.

Каждый ключ потока нумеруется с единицы.
Квитанция хранит порядковый номер заказа, который обработчику даёт [`Ctx<Position>`](../components/positions/position.md), поэтому читатель может позже [вернуться](resume-and-seek.md) к этому заказу.
Следующий запуск, который дописывает в тот же файл, продолжает нумерацию: после перезапуска следующий заказ получает номер три, а не один.

Файл растёт без ограничения, если его размер не ограничивает [`size_limit`](../components/broker/size-limit.md).
Что предел значит для долгоживущего файла, разбирает руководство [Промышленная эксплуатация](production.md).

[`replay()`](../components/subscriptions/replay.md) запускает воспроизведение: оно читает то, что файл хранит под ключом `receipts`, с первого сообщения и завершается в конце файла.
Квитанцию, дописанную после этой точки, оно не читает, поэтому задание делает свой проход, и ждать ему больше нечего.
С [`existing_only`](../components/broker/existing-only.md) запуск возвращает ошибку, если файла нет, поэтому опечатка в пути останавливает задание, а не создаёт пустой файл.

`total` принимает срез, а [`batch(nonzero!(64))`](../components/subscriptions/batches.md) в точке монтирования ограничивает пакет 64 квитанциями.
Пакет берёт то, что уже есть в файле, и не ждёт заполнения. Один исход завершает весь пакет.

Писатель помечает файл законченным через [`end_with_eos`](../components/broker/end-with-eos.md): при завершении работы он дописывает метку конца потока.
Воспроизведение на метке завершается, а живая подписка, такая как `notify`, на ней заканчивается.

## Тестирование журнала {/* #testing-the-log */}

Тесты в файле примера запускают магазин и аудит на внутрипроцессном транспорте: заказ получает квитанцию, и `notify` её читает, а аудит читает три записанные квитанции одним пакетом и пропускает четвёртую.
Квитанции для аудита записываются через клон его брокера до запуска, так, как их оставил бы магазин.
Тест перезапуска дважды запускает магазин на одном настоящем файле через [`TestApp::start_live`](../components/testing/live.md) и проверяет, что второй запуск даёт своему заказу номер три.
Оба режима разбирает руководство [Тестирование сервиса на файле или в конвейере](testing.md).
