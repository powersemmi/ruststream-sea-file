# Путь

Путь одного сообщения через сервис RustStream, на файле потока и в канале: чтение, очередь,
обработчик, ответ и запись.

<Diagram name="path" words={words} />

На файле задача подписки читает с опережением обработчика. Она забирает у клиента каждое сообщение,
сохраняет прочитанные байты, и [конверт](envelope.md) находит в них полезную нагрузку. Затем задача
ставит доставку в очередь, в которой помещается до 64 доставок. Обработчик читает из этой очереди,
поэтому следующее сообщение уже прочитано из файла, пока обрабатывается текущее.

В канале с опережением читает поток чтения процесса. Он ставит каждую строку в очередь подписок её
ключа, без ограничения длины, а конверт находит полезную нагрузку, когда обработчик просит
следующее сообщение.

На обоих транспортах заголовки разбираются при первом обращении к ним, вместе с номером сообщения в
заголовке [`stream-sequence`](../components/headers/sequence-header.md). Если обработчик читает
только полезную нагрузку, заголовки не разбираются вовсе.

На файле каждая доставка несёт поколение, в котором был читатель, когда её прочитал.
[Перемотка](seeking.md) открывает новое поколение, и подписка отбрасывает то, что стоит в очереди
под старым. Доставка также держит разделяемую ссылку на дескриптор перемотки подписки, поэтому
построение её контекста на каждом сообщении только увеличивает счётчик ссылок.

Ответ обработчика кодируется в буфер, который цикл диспетчеризации использует повторно. Если конверт
оставляет эти байты как есть, издатель передаёт их клиенту без копирования. Конверт по умолчанию
оборачивает их, только когда у сообщения есть заголовки, или в канале, когда строка изменила бы
полезную нагрузку. Публикация в
файл возвращается, когда дозапись сброшена в файл. Ответ, записанный в тот файл, который читает
подписка, её читатель пропускает: ответ лежит под другим ключом потока.

Доставка завершается после ответа. На обоих транспортах ack и nack возвращают ошибку: операция не
поддерживается. Это показывает страница [Завершение](settlement.md).
