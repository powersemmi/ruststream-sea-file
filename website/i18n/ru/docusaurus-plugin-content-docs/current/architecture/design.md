# Устройство

Где стоит `ruststream-sea-file`: между рантаймом RustStream и двумя клиентами sea-streamer, один
столбец для файла потока и один для канала.

<Diagram name="design" words={words} />

Крейт реализует трейты брокера из ядра поверх двух клиентов
[sea-streamer](https://github.com/SeaQL/sea-streamer): `sea-streamer-file` для файла потока и
`sea-streamer-stdio` для стандартного вывода процесса и формата строки; стандартный ввод крейт
читает сам, в том же формате. Рантайм над ним один для всех
брокеров. Всё, что относится к файлу или каналу, лежит в этом крейте:
[дескриптор](../components/subscriptions/file-stream.md), [позиции и
перемотка](../components/positions/index.md), [смысл ack](../components/settlement/index.md),
[адрес копии для повтора](../components/settlement/retry-after.md) и передача заголовков.

Подключённый брокер держит одну связь со своим транспортом. Для файла это стример клиента, один
продюсер, через который дописывает каждая публикация, и рантайм, на котором выполнился `connect`.
Для stdio это стример клиента и признак того, замкнут ли брокер на себя. Все клоны брокера делят одну связь. Поэтому
брокер, подключённый дважды, подключается один раз, а издатель, выданный до подключения, находит
связь при первой публикации.

Каждая задача файлового соединения выполняется на рантайме, на котором выполнился `connect`, а
стандартный ввод читается в собственном потоке. Поэтому подписка, открытая из другого рантайма,
продолжает доставлять сообщения после остановки того рантайма.

Файловая подписка - это управляющая задача, которая владеет консьюмером клиента. Перемотке клиента
консьюмер нужен в единоличное пользование, и прервать её нельзя. Она передаёт сообщения через
очередь на 64 места. Подписка stdio читает очередь, которую наполняет поток чтения процесса. Оба
транспорта читают по одному сообщению, поэтому [пакет](../components/subscriptions/batches.md) собирает крейт. Неполный пакет
уходит через 10 миллисекунд после своего первого сообщения.

Ни один транспорт не принимает настроек на сообщение, поэтому у публикации нет параметров. Клиенты
принимают полезную нагрузку без заголовков, поэтому заголовки передаются внутри полезной нагрузки,
в [конверте](envelope.md).

Как части запускаются и останавливаются, показывает страница [Жизненный цикл](lifecycle.md), а
путь одного сообщения - страница [Путь](path.md).
