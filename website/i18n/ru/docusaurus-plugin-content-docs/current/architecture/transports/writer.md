# Запись

Одна задача записи на файл потока оформляет каждое сообщение в кадр и расставляет маяки. Крейт
сбрасывает файл после каждой публикации, а при завершении работы файл синхронизируется с
устройством.

<Diagram name="writer" words={words} />

Издатель [`FilePublisher`](../../components/publishing/file-publish.md) передаёт ключ потока и
полезную нагрузку продюсеру клиента. Продюсер ставит их в очередь задачи записи файла. Задача нумерует
сообщение в пределах его ключа, оформляет в кадр и вставляет маяк там, где наступает следующий
интервал.

Байты копятся в буфере, пока их кто-нибудь не запросит. Крейт запрашивает их после каждой
публикации: `publish` возвращается, когда сброс передал сообщение операционной системе. Живой
читатель того же файла, в этом процессе или в другом, видит сообщение с этого момента.

Файл синхронизируется с устройством один раз, когда завершается продюсер. Крейт завершает его при
[завершении работы](../../components/broker/shutdown.md), после метки конца потока, если она
задана. Сообщение, опубликованное после последней синхронизации, переживает сбой процесса, но не
отключение питания.

Все продюсеры одного файла в процессе делят одну задачу записи, которая считает дескрипторы
продюсеров. Открытие продюсера на файле, где уже есть сообщения, просматривает файл назад до
последнего маяка и вперёд до конца, чтобы узнать, где стоит нумерация каждого ключа. Этот просмотр
растёт вместе с файлом. Крейт передаёт задаче записи по одной дозаписи на файл, поэтому
неудачная дозапись не оставляет других публикаций в ожидании.

Клиент ограничивает файл 16 ГиБ, если не задано иное, а этот крейт велит ему обходиться без
предела, пока его не задаст [`size_limit`](../../components/broker/size-limit.md). Публикация, которая достигает предела, возвращает ошибку, и каждая следующая публикация
в этот файл сразу возвращает ту же ошибку.
