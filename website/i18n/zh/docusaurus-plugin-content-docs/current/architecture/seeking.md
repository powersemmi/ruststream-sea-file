# 定位

处理器通过[定位句柄](../components/positions/seek.md)移动它自己的文件订阅：驱动任务执行客户端的定位，从旧位置排入队列的内容被丢弃。

<Diagram name="seeking" words={words} />

客户端的定位需要独占消费者，而且不能中途打断。因此，订阅的驱动任务独占消费者，定位以命令的形式到达它。驱动任务把定位执行到完成，不与下一次读取竞争，完成后答复处理器。

[`FilePosition`](../components/positions/index.md) 转换为客户端的目标。开头和末端直接对应。序号是包含在内的，因此定位到从某次投递读到的位置，会再次投递那条消息。以毫秒计的时刻转换为纳秒，超出范围的值在到达客户端之前就被拒绝。

移动了读取者的定位会开启一个新代号，驱动任务在答复之前公布它。订阅丢弃每个带有更旧代号的投递，因此 `seek` 返回之后，在旧位置读到的任何内容都不会到达处理器。

被拒绝的定位，例如超过最后写入序号的序号，会让重放留在原处，已读到的内容仍在队列中。实时订阅则会结束：客户端向前读取寻找这条消息，读完了文件。已到达文件末尾的重放仍然可以定位，并从新位置再次投递。

通道已满时，定位照常得到处理。停止从通道取消息的处理器，可能正是在等待定位的那一个，因此比通道更大的积压永远不会阻塞它。关闭之后，每次定位都会被拒绝。

[进程内传输](in-process.md)以同样的方式移动订阅，拒绝的情形也相同，只是在订阅自己的轮询中完成。
