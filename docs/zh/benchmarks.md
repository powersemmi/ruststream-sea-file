# 基准测试 { #benchmarks }

在流文件和你的代码之间，任何一层都要在每条消息上花时间：订阅的流、解码、确认、分发。这一页说明它
花了多少，参照物是同样的活用 `sea-streamer-file` 手写一遍。

每个场景在同一个进程里跑三遍，三个循环之间只差一件事：由谁来搬运消息。

- **裸客户端** —— 直接驱动 `sea-streamer-file`：它的 streamer、它的消费者、它的生产者。
- **这个 crate** —— 手工驱动 crate 自己的类型：Broker、订阅描述符、它交出的流、投递的载荷和它的
  确认、发布者。没有处理器，也没有运行时。
- **RustStream 服务** —— 用户真正写的东西：`#[subscriber]` 处理器、应用、运行时。

其余一切都保持相同：流文件、消费者选项、解码成同一个类型、载荷字节、tokio 运行时和构建。这套流程
属于框架本身，写在
[RustStream 基准测试页](https://powersemmi.github.io/ruststream/latest/zh/benchmarks/#methodology)
上；这一页公布它在这台机器上得出的结果。

两个开销列回答的是不同的问题。「crate 开销」是这个 crate 自己的消费者和发布者相对于它所包装的库
多花的代价，这正是这个仓库要负责的部分。「框架开销」是整个服务对同一个裸客户端，所以两列之间的
距离就是运行时在这个传输上额外加的那一份。

场景有两个，因为流文件有两种读法。重放读的是订阅打开之前就已经写完的文件，没有任何东西为它定速：
分发开销在这里完整显现，而不是藏在等待里面。实时跟随读的是还在被追加的文件，那里每一次投递都要
等一次写入落到磁盘上。

标为「无法区分」的一行，是两端之间的差值小于各自多次运行之间离散范围的那一行。低于运行噪声的数字
读起来像是从未测到过的精度，所以不公布。

同一次运行的机器可读形式在
[`benchmarks/results.json`](https://powersemmi.github.io/ruststream-sea-file/latest/benchmarks/results.json)，
框架的站点用它拼出跨 Broker 的汇总表。

## 机器 { #the-machine }

<div id="benchmark-environment"></div>

这一行里没有 Broker，也没有网络。这里的传输就是一个文件，所以占据服务器位置的是文件系统，这些
数字属于它的程度不亚于属于这个 crate：同样的代码放在更慢的设备上，公布出来的数字也更慢。

一行上的「受存储限制」标记是拿上面公布的往返时间算出来的，不是猜的。一次落盘的写入正是这个传输让
投递去等的东西，所以它在三个循环之外单独计时；当一次这样的写入至少要花掉一条消息开销的一半时，
这一行就会被标记。这样的一行是分发开销的下界，不是对它的测量。

页缓存的状态比其余一切都更要紧。从内存里读的重放和从设备上读的重放，两者之差远大于这一页要讲的
开销，所以每一次运行都在读回之前刚刚写下自己的流文件，公布的是前一种。

构建标志和数字一起公布，因为它们会改变这些数字。用 `-C target-cpu=native` 构建出的二进制给出的
结果，换一台机器就复现不了，所以这条 recipe 在构建前先把这个变量清空。

## 这些数字不代表什么 { #what-they-do-not-mean }

这里只有一个订阅、一个流键、一个很小的消息体和一个文件。它测的是一次投递在这个 crate 里的开销，
不是磁盘能读多快。这里的一行也不能拿去和另一个 Broker 公布的一行比较：不同的传输在每条消息上做的
事并不一样。

一次运行的测量窗口从第一次投递开始，到最后一个处理器返回为止，三个循环都是这样。全程不做确认：
这个传输不保存消费者的位置，所以确认会如实报告自己不受支持，而不是假装成功；裸客户端则根本没有
可确认的东西。

重放场景在一个点上偏离了框架的流程，而且是故意的：它的订阅是在消息写完之后才打开的，因为重放本来
就是这么一回事。先挂上再喂数据的那个场景是实时跟随。

这些数字是一台机器在某一天的快照。它们按需重测，从不放进 CI：共享 runner 的噪声比这一页要讲的
差值还大。

## 自己跑一遍 { #running-it-yourself }

```bash
just bench
```

这条 recipe 把运行指向 `target/` 下的一个目录，让每个场景跑完三个循环，删掉流文件，然后把测到的
结果写回 `docs/benchmarks/results.json`。它要花一刻钟左右，会往这个目录里写入几十 GB，并且需要
整台机器。消息条数不是固定的：一次试探运行会把它定下来，使得每一次被测量的运行都不短于五秒，上限
是两百万条消息，大约一个 GiB 的流文件；再往上，一次运行测的就是设备而不是这个 crate 了。
