    Lifecycle

    FileBroker::new records a path, connect opens the file, each subscription opens a reader, and shutdown ends the writer; StdioBroker attaches the process's pipes on first use.

    new does no I/O, so the service's builder stays synchronous. The runtime connects the broker when the app starts. Connect creates the file when it is missing, or fails under existing_only. It checks the beacon interval, opens the client's streamer and one producer, and writes the priming message into a file that holds nothing yet.

    Each subscription opens its reader on the runtime connect ran on: a consumer at the tip for a live subscription, or a reader of the whole file for a replay. A publish appends and flushes, as Writer draws.

    Shutdown marks the connection closed first, so a publish that starts after it fails. It then waits for the publishes in flight and takes the producer out. The client ends the file's writer: it writes the end-of-stream mark when it is set, flushes, and syncs the file to the device. The crate drops its producer only after that and asks the client once more. A handle dropped late would otherwise end the writer of the next connection to the same file.

    After shutdown, a publisher kept from before returns NotConnected, and a seek through a seeker kept from before is refused. Neither reports a success against the closed file.

    The stdio broker​

    Connect records whether the broker loops back and touches no pipe. The first subscription in the process starts the reader thread of standard input, and the first publish the client's stdout thread, as Pipe draws. Both threads serve the whole process, so a shutdown ends every stdio subscription and producer in it, those of other brokers included. The end of standard input ends the subscriptions too, those of a broker under loopback excepted.
